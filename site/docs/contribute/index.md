# 我的机型还没支持

本项目的目标是把能装的 IPQ50xx 路由器都收录进来，但维护者手里的机器有限，很多机型需要大家帮忙。

## 收录一个机型要经过哪几步

1. **收集资料**：分区表、NAND 型号、安全启动状态、原厂的双系统方式。
2. **写机型资料**：每个机型一份数据文件，放在仓库的 `devices/` 目录。本站的页面和安装程序的检查项都从这里来。
3. **实机验证**：由能接 TTL 的人走完整个流程，状态变成「已验证」或「社区验证」后才对普通用户开放。

## 你可以怎么帮忙

- **提供资料**：本站会提供一个**只读**的采集脚本（准备中），在原厂 SSH 里运行，输出一份报告贴到 Issue 即可。它不会写入任何东西，也不读取校准分区，并会去掉 MAC 和序列号。
- **帮忙测试**：手里有 TTL 串口的，可以认领「测试中」的机型，或者给「未验证」的机型做[RAM 试跑](#ram-试跑)，不写闪存，断电就恢复。
- **补充教程**：知道某个机型怎么打开原厂 SSH 的，欢迎提供链接和步骤。

::: warning 请不要上传
整片闪存备份、ART 分区、原厂固件文件。它们要么包含你这台机器的私有数据，要么有版权问题。我们只需要分区布局、大小和哈希值。
:::

## RAM 试跑

「未验证」的机型没有人在实机上跑过。最安全的验证方法是 **RAM 试跑**：把本项目的 U-Boot 加载到内存里运行一次。**整个过程不写任何闪存，断电就恢复原样。**

需要：能接 TTL 串口、一台电脑做 TFTP 服务器（电脑网线接路由器的 LAN 口）、对应机型的 RAM 试跑包。试跑包的名字是 `<构建名>-untested-ram.uimg`，构建名写在每个机型页的「构建名」一栏，文件在 [Releases](https://github.com/FlyFish-go/IPQ50XX-Uboot/releases) 或 CI 构建产物里。

::: danger 先说清楚
RAM 试跑成功**不代表**可以刷入。它只是让这块板第一次有了实机反馈。没有维护者确认「已验证」之前，请不要把这个 U-Boot 写进闪存。
:::

1. **接串口，进原厂 U-Boot。** 串口 115200 8N1，先确认电平（很多机型是 1.8 V，接 3.3 V 会损坏）。通电后在提示 “Hit any key” 时按键打断自动启动。个别机型需要密码，小米机型默认关了串口输出（见各机型页）。
2. **记下设备树地址。** 在原厂 U-Boot 里执行 `printenv fdtcontroladdr`；没有这个变量就执行 `bdinfo`，看 `fdt_blob` 一行。每个机型不一样，**不要照抄别人的地址**。
3. **设网络，把试跑包下载到内存。** 电脑设成和路由器同一网段（例如 `192.168.1.2`），把试跑包放在 TFTP 目录，然后：

   ```
   setenv ipaddr 192.168.1.1
   setenv serverip 192.168.1.2
   tftpboot 0x44000000 <构建名>-untested-ram.uimg
   ```
4. **启动。** 用第 2 步记下的地址：

   ```
   bootm 0x44000000 - <fdtcontroladdr 的值>
   ```

   这里必须用 `bootm`，原厂 U-Boot 不允许直接跳到内存里的程序。
5. **检查，并记录结果。**
   - 串口有没有出本项目 U-Boot 的启动横幅，横幅里有没有「untested」字样；
   - 闪存型号和 ECC 识别那几行；
   - 每个网口：网线接上有没有 link，电脑能不能 ping 通；
   - 救援页：串口里输入 `httpd`，浏览器打开 `http://192.168.1.1`，页面能不能打开（一次只接一根网线）；
   - 按 Reset、WPS / Mesh 键，有没有响应；LED 亮不亮、什么颜色。
6. **断电。** 重新上电，路由器会按原样启动原厂系统。整个过程没有写过闪存。

不要在这一步里点救援页的「写入」「刷新」或 U-Boot 里的 `saveenv`、`nand write`、`bootconfig set` 之类命令。

测完请[提交试跑报告](https://github.com/FlyFish-go/IPQ50XX-Uboot/issues/new?template=board-report.yml)：机型、机身贴纸上的版本、启动日志、闪存型号、救援页结果、LED 和按键。启动日志里的 MAC 地址和序列号请先打码。
