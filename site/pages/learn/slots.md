# 双系统怎么切换

很多 IPQ50xx 路由器出厂就有两个系统槽：升级时写另一个槽，写坏了还能从原来那个启动。不同厂家用不同的办法记录「下次从哪个槽启动」。

## 本项目的原则

- 原厂是双系统的，照原厂逻辑来。U-Boot 读写的标志和原厂完全一致，所以原厂固件自己的升级、OpenWrt 的 `sysupgrade` 都照常能用。
- 原厂是单系统的，保持单系统。不去改分区表硬塞第二个系统，免得和原厂固件冲突。
- 大分区是可选项。双系统机型可以把两个槽合并成一个大分区，给第三方固件更多空间。这个功能只在实机验证过的机型上开放（目前是 H3C）。

## 常见的几种切换方式

| 方式 | 记录在哪 | 典型机型 |
|---|---|---|
| BOOTCONFIG | 闪存里的 `0:BOOTCONFIG` / `0:BOOTCONFIG1` 分区 | H3C NX30 家族、LYW-30M、锐捷 RG-MA3063、中国移动 MR3000D-CI、ELECOM、I-O DATA |
| 小米环境变量 | U-Boot 环境变量 `flag_boot_rootfs`、`flag_try_sys*_failed` 等 | 小米 CR880x、AX6000，红米 AX5400 |
| TP-Link 环境变量 | U-Boot 环境变量 `tp_boot_idx` | TP-Link Archer AX55、RE700X，Mercusys MR80X v2 |
| Linksys 环境变量 | U-Boot 环境变量 `boot_part` | Linksys MX / MR 系列 |
| 单系统 | 只有一个系统槽 | GL.iNet、Zyxel 等 |

这张表来自上游 OpenWrt 的设备支持代码和我们自己的调研。列在这里不等于已经支持，以[机型列表](/devices/)里的状态为准。本项目目前实现了 BOOTCONFIG 和小米环境变量两种。

## 和原厂不完全一样的地方

照原厂逻辑不代表每个细节都照搬。差异写在各机型页的「和原厂不一样的地方」。例如锐捷 RG-MA3063 的原厂 U-Boot 有一个开机计数，连续多次没启动成功会自动切到另一个槽，本项目没有照搬。

## 为什么每个机型都要先用 TTL 验证

将来普通用户会从原厂系统里安装（[系统内安装](/install/shell)），不用拆机。代价是：如果新 U-Boot 起不来，没有 TTL 就救不回来。所以每个机型都要先由能接 TTL 的人实机走通，确认能救，再对普通用户开放。
