# 系统内安装（Telnet / SSH）

系统内安装测试版 [shellinstall-test.1](https://github.com/FlyFish-go/IPQ50XX-Uboot/releases/tag/shellinstall-test.1) 已发布，**只支持锐捷 RG-MA3063 硬件 1.00**，[步骤见下](#ma3063-install)。其他机型还没开放，按机型页上写的方式：H3C 用 [BootBridge 网页安装](/install/bootbridge)，其他机型用 [TTL 串口安装](/install/ttl)。

## 是什么

不用拆机：在原厂系统里打开 Telnet 或 SSH，拿到 root 命令行，运行我们的安装程序。安装程序自己核对这台机器、备份、写入 U-Boot、读回核对，任何一项不对就停下。

这是将来给普通用户的主要安装方式。TTL 只留给每个机型的第一位验证者，以及出了问题需要救砖的时候。

## 为什么还没开放

- 每个机型拿 root 的方法都不一样：有的原厂自带 SSH，有的要靠社区工具，有的要利用原厂网页的漏洞，有的根本没有公开方法；
- 原厂内核可能把 U-Boot 所在的分区设成只读，这时从系统里写不进去，要先确认；
- 从系统里写坏了，没有串口就救不回来。所以每个机型都要先有人用 TTL 实机走通、确认能救，再对普通用户开放。

## 安装程序会核对什么

写入之前，下面每一项都要对得上，否则拒绝写入：

1. 机型：设备树里的主板型号和原厂固件标记都与机型资料一致；
2. 分区表的名字、大小、偏移和机型资料一致；
3. 安全启动没有开启：`/sys/devices/system/qfprom/qfprom0/authenticate` 必须是 `0`；
4. U-Boot 所在分区能读、能写；
5. 安装包里有这个机型的 U-Boot。

还会读出两份 U-Boot，确认没有坏块、能完整读出，并从 BOOTCONFIG 判断正在用的是哪一份。

然后把启动相关的分区打包成备份，必须在浏览器里下载完才允许写入。写入时先写备用的那份 U-Boot，再写正在用的那份，每份写完逐字节读回核对。

## RG-MA3063：开启原厂 SSH { #ma3063-stock-shell }

RG-MA3063 硬件 1.00 样机已通过工厂接口开启原厂系统的 SSH 和 Telnet，以 `admin` 登录后确认是 Linux root。**重启后两者都会关闭**，每次重启后要重新访问下面第 2 步的地址。

### 开启与登录

1. 拔掉 WAN 网线，电脑用网线连接设备的 LAN 口，先确认能打开原厂管理页。默认地址为 `192.168.10.1`，改过地址的使用当前地址。此接口会开启调试服务，使用公开工厂口令，请在隔离的管理网络内操作。
2. 浏览器访问 `http://192.168.10.1/__factory_verify_mode__`。样机返回：

   ```json
   {"result": "Pass"}
   ```

3. 在电脑终端连接 SSH：

   ```sh
   ssh -o HostKeyAlgorithms=+ssh-rsa admin@192.168.10.1
   ```

   首次连接先核验并保存主机密钥，密码输入公开工厂口令 `wifi@cmcc`。样机的旧版 Dropbear 需要上述 `ssh-rsa` 主机密钥兼容选项。
4. 登录后执行 `id`。样机实测输出：

   ```text
   uid=0(root) gid=0(root)
   ```

   登录名虽然是 `admin`，实际权限是 root。随后可以运行 `cat /proc/mtd` 等只读检查；本节不包含安装或分区写入命令。

### 验证范围

- 样机资料：硬件 1.00，AP-MP02.1，machid `0x8040000`。本次读取的系统标识为 `wuhu-cmcc-main`，内核为 `4.4.60`，编译时间为 2022-01-13；本次没有重新核对完整原厂固件版本号。
- 开启前 22/23 端口均拒绝连接；接口返回成功后两者开放，SSH 和 Telnet 都能以 `admin` 登录，root 权限已确认。
- 断电重启后 22/23 又拒绝连接，重新访问工厂地址后恢复。
- 没有测试 V3、V4、MA3064 或其他固件版本。

方法来源：[锐捷 RG-MA3063 开启 SSH 的方法](https://blog.kokomi.me/posts/enable-ssh-for-rg-ma3063/)。以上范围内的结果已由项目维护者在样机上复现。

### 安装测试版 { #ma3063-install }

先完成上面的「开启与登录」，然后：

1. 打开 [shellinstall-test.1 发布页](https://github.com/FlyFish-go/IPQ50XX-Uboot/releases/tag/shellinstall-test.1)，把 `command.txt` 的**全部内容**复制粘贴到 SSH 里回车。它有几十行，是一条命令。
2. 命令会先试着从 GitHub、Gitee 下载安装包。路由器连不上外网时，会提示打开上传页：把发布页上的 `ipqi-shellinstall-test.1.bin` 下载到电脑，再在上传页选择它。页面地址以命令输出为准，一般是 `http://192.168.10.1:8089/`。
3. 安装页上依次：看核对结果 → 生成备份并下载保存 → 写入 → 重启。

重启后 SSH 会关闭，原厂系统照常启动。备份里有这台机器的校准数据和 MAC，不要上传到网上。

### 台架上的系统内安装 { #ma3063-bench }

在同一台样机上，先把两份 U-Boot 恢复成原厂版本（2022-01-13），冷启动确认回到原厂 U-Boot，然后按用户的步骤操作：开启 SSH，粘贴安装命令，路由器连不上外网时在浏览器上传安装包，核对、下载备份、写入。

- 核对全部通过：机型、分区表（20 个分区）、安全启动未开启、U-Boot 分区可写、没有坏块、两份都能完整读出、启动选择记录；
- 备份里两份 U-Boot 和原厂版本一致；没下载备份时点安装会被拒绝；
- 两份 U-Boot 写入后读回一致，之后断电冷启动 9 次，每次都由本 U-Boot 启动原厂系统，约 65 秒后 LAN 可以访问；
- 原厂系统自己的 LuCI 占用了 8088 端口，安装页自动改用 8089；页面地址以命令输出为准；
- 原厂命令行一行最多 1023 字节，所以安装命令分成多行，仍是一次粘贴。

之后用测试版的正式安装包，在浏览器里完整走了一遍：从旧开发版升级到 v0.2.0，写入、点页面上的重启都正常，之后冷启动 9 次正常。

只验证了这一台样机。写入失败时需要 TTL 串口救回。

## 你能帮什么忙

- 告诉我们拿 root 的方法：你的机型怎么在原厂系统里打开 Telnet 或 SSH，附上来源链接，发到 [GitHub Issues](https://github.com/FlyFish-go/IPQ50XX-Uboot/issues)；
- 提供只读资料：在原厂命令行里执行 `cat /proc/mtd` 和 `cat /sys/devices/system/qfprom/qfprom0/authenticate`，把输出贴到 Issue 里（不含私密信息）；
- 请不要上传整片闪存备份、ART 分区或原厂固件文件。
